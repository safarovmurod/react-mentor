# DevAtlas: запуск с компьютера и публикация

Эта инструкция относится к `safarovmurod/react-mentor`. Репозиторий `react-practice` — отдельный проект. Настройка облачной среды Codex сама по себе не публикует сайт в Vercel и не настраивает Supabase.

## 1. Открыть актуальную версию в GitHub

Откройте [основную ветку react-mentor](https://github.com/safarovmurod/react-mentor/tree/main). Владелец отменил прежнее требование Private и разрешил публичный push и merge. Обновления DevAtlas уже отправлены в `main`; менять видимость репозитория для получения этих обновлений не требуется.

Vercel автоматически начал публикацию после обновления `main`. На рабочем адресе `/api/courses` уже проверены 38 курсов, а неавторизованный запрос премиального материала возвращает 401. Это подтверждает публикацию кода, но не заменяет последующую проверку живых аккаунтов и базы.

## 2. Подготовить компьютер и открыть проверенную ветку

Установите Node.js 24 LTS, Git и VS Code с официальных сайтов. Python 3 нужен для части проверок примеров. Для полноценной проверки отдельных языков также нужны соответствующие локальные инструменты; наличие подсветки в редакторе сайта не означает наличие компилятора.

Когда новая ветка уже отправлена, откройте терминал VS Code в папке, где будете хранить проект:

```bash
git clone --branch main https://github.com/safarovmurod/react-mentor.git
cd react-mentor
npm ci
npm run typecheck
npm run lint
npm run test -- --maxWorkers=2
npm run build
```

Если репозиторий уже скачан, не скачивайте поверх существующей папки и не удаляйте изменения. Сначала посмотрите `git status`; обновление существующего рабочего проекта нужно выполнять с сохранением вашей работы. При запросе доступа войдите в свой GitHub через стандартное окно авторизации, не вставляйте токен в ссылку репозитория.

Для открытия сайта только на своём компьютере:

```bash
npm run dev
```

Откройте адрес, напечатанный терминалом. Это локальный запуск, а не публичная ссылка. Чтобы остановить свой сервер, нажмите Ctrl+C в его терминале.

## 3. Сначала проверить базу на тестовом Supabase-проекте

Откройте [Supabase Dashboard](https://supabase.com/dashboard). Для репетиции используйте отдельный тестовый проект. Существующий проект владельца `sqveszluhdargkiqowjp` может обслуживать и другое приложение: не удаляйте его таблицы, пользователей, провайдеры или прежние адреса возврата.

Сохраните резервную копию рабочей базы и убедитесь, что умеете её восстановить. Перед применением проверьте, какие миграции уже выполнены. Их нельзя слепо запускать повторно.

В тестовой базе разработчик проверяет миграции в таком порядке:

1. `supabase/migrations/20261004000000_accounts.sql`.
2. `supabase/migrations/20261005000000_progress_conflict.sql`.
3. `supabase/migrations/20261022000000_verified_practice.sql`.
4. `supabase/migrations/20261022010000_memberships_chat.sql`.

Первые две миграции могут уже присутствовать в рабочем проекте. Старую `20261001000000_init_schema.sql` не нужно добавлять в эту последовательность автоматически: самостоятельные аккаунты используют отдельные таблицы с префиксом `react_mentor_`. Подробности — в [accounts-setup.md](accounts-setup.md).

Сначала убедитесь на тестовых аккаунтах, что пользователь A не читает и не изменяет приватные записи пользователя B, повторная сдача не увеличивает защищённые XP дважды, просроченная подписка закрывает премиальный доступ, а чат не принимает поддельного автора. Только после этого применяйте ещё не применённые миграции к рабочему проекту. Не используйте удаление таблиц как способ исправить ошибку миграции.

## 4. Добавить параметры подключения безопасно

Для локального теста скопируйте структуру `.env.example` в новый файл `.env.local`, если его ещё нет. Существующий файл не перезаписывайте. Заполните значения из настроек нужного Supabase-проекта:

| Имя | Что выбрать |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | URL выбранного Supabase-проекта |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Публичный publishable/anon ключ этого же проекта |
| `SUPABASE_SERVICE_ROLE_KEY` | Секретный серверный service-role ключ для защищённой проверки HTML |
| `AI_TUTOR_ENABLED` | Оставить `false`, если онлайн-AI не подключён |

Service-role ключ даёт привилегированный доступ: вводите его только в закрытые настройки сервера или локальный игнорируемый `.env.local`. Никогда не помещайте его в `NEXT_PUBLIC_*`, исходники, сообщения, скриншоты или GitHub. Не требуется отправлять ключи в чат. `SUPABASE_ACCESS_TOKEN` — отдельный необязательный управленческий токен для разовой настройки, а не обязательный ключ работающего сайта.

Не открывайте `.env.local` на демонстрации экрана. После изменения параметров перезапустите локальный сервер. Публичные переменные Next.js включаются при сборке, поэтому для Vercel потребуется новая сборка.

## 5. Настроить вход в аккаунт

В Supabase откройте **Authentication**. Проверьте разрешение email-регистрации и подтверждения email. Для регистрации посетителей нужен корректно настроенный SMTP: стандартная отправка Supabase имеет ограничения и не доказывает, что письма получат все пользователи.

Для Google настройте OAuth-провайдер в Supabase и его callback в Google Cloud. Используйте callback именно выбранного Supabase-проекта. Секрет Google остаётся в настройках Supabase.

В **URL Configuration → Redirect URLs** добавьте адреса вашего сайта:

- `https://ВАШ-ДОМЕН/auth/callback`
- `https://ВАШ-ДОМЕН/auth/callback?recovery=1`

`ВАШ-ДОМЕН` здесь нужно заменить настоящим доменом Vercel. Сохраните существующие адреса другого приложения. Тестовые локальные адреса добавляйте только для соответствующей тестовой среды. Полный Google-вход проверяется реальным переходом и возвратом в сайт; открывшаяся страница Google сама по себе ещё не означает успешный вход.

## 6. Создать пробную публикацию в Vercel

Откройте [Vercel](https://vercel.com), войдите через GitHub и предоставьте доступ только к нужному закрытому репозиторию. Если проект `react-mentor` уже существует в Vercel, откройте его; не создавайте случайный второй production-проект и не отключайте прежний рабочий домен.

Для нового проекта выберите **Add New → Project → Import react-mentor**. Настройки:

- Framework: **Next.js**.
- Root Directory: корень репозитория, обычно `.`. `/workspace/react-mentor` — путь облачной машины, его сюда вводить не нужно.
- Install Command: `npm ci`.
- Build Command: `npm run build`, чтобы выполнялась подготовка локального редактора через `prebuild`.
- Node.js: **24.x**.
- Output Directory: стандартное значение Next.js, без ручного указания `dist`.

В **Settings → Environment Variables** добавьте параметры из шага 4 через защищённый интерфейс Vercel. Для Preview используйте тестовую базу и тестовые ключи; для Production — рабочую базу и её ключи. Не включайте ключ service-role в публичные переменные.

Сначала создайте Preview из ветки `feat/devatlas-learning-platform`. Добавьте точный callback Preview в тестовый Supabase, если проверяете вход. Проверьте Deploy Logs: сборка должна завершиться успешно, редактор должен иметь локальные файлы. Не отключайте проверки сертификатов или целостности пакетов ради успешной сборки.

После успешной проверки Preview выполните обычное ревью и объединение в настроенную production-ветку или предусмотренное Vercel продвижение проверенной сборки. Настройки Production и домен должны указывать на рабочую базу. Не считайте старый deployment обновлённым только потому, что переменные сохранены: нужна новая успешная публикация.

## 7. Проверить реальный адрес перед приглашением пользователей

Откройте выданный Vercel HTTPS-адрес в обычном браузере и отдельно на телефоне. Проверьте:

1. Каталог показывает 10 категорий, программирование — шесть направлений. Поиск находит нужный курс, карточка открывает именно его.
2. Длины планов соответствуют опубликованным материалам: двухдневный модуль не превращается в 30 пустых дней, CSS содержит 5, Next.js — 20 дней.
3. Новый пользователь начинает с дня 1. После теории, практики и отдельного подтверждения появляется следующий доступный день. Перезагрузка сохраняет результат; незавершённый день нельзя обойти прямой ссылкой в учебном интерфейсе.
4. Редактор открывается при переходе в практику, показывает подсказки и ошибки в поддерживаемых языках. Справка и образец скрываются и открываются. Правильное альтернативное имя переменной не делает решение ошибочным.
5. HTML дня 1 проходит реальную проверку; неправильный документ не засчитывается. Серверный защищённый результат появляется только при работающем входе, миграциях и серверной настройке.
6. Реальный вход Google, подтверждённый email, выход, повторный вход и смена аккаунта не смешивают личный прогресс. На втором устройстве проверьте тот же аккаунт. Данные гостя сами собой не становятся чужими аккаунтными данными.
7. Гость и Starter не получают платные уроки, ответы, tutor-справку и premium-only файлы через прямой API. Pro открывает четыре Pro-модуля, но не Expert. Expert открывает оба уровня. При недоступной базе доступ закрывается, а не выдаётся автоматически.
8. В HTML/RSC-ответе неавторизованной страницы нет платного текста и решений. В инструментах браузера/Network проверить также прямые запросы к API. Скрытая кнопка без серверного запрета не является защитой.
9. При настоящей активной подписке чат показывает реальные сообщения и присутствие. После выхода, истечения доступа или потери связи данные не остаются доступными как активная приватная сессия; статус присутствия имеет срок действия.
10. Переключение русского, таджикского, английского, японского, корейского и украинского интерфейса сохраняется. Перевод интерфейса не выдаёт непереведённый учебный материал за готовый перевод.

Здесь описаны приёмочные действия для живого deployment, а не утверждение, что они уже выполнены. Автоматические тесты с моделируемым Supabase не заменяют эти проверки. Реальный доступ к рабочим аккаунтам и хостингу требуется отдельно.

## 8. Подписки: что работает и что ещё нужно подключить

Четыре Pro-модуля и один Expert-модуль опубликованы и защищены проверкой серверного membership. Платёжный провайдер ещё не интегрирован: checkout возвращает `billing_not_configured`, не списывает деньги и не выдаёт подписку. Не принимайте оплату, пока этот путь не реализован и не проверен.

Для ограниченного теста владелец базы может создать временный membership только через доверенный административный доступ: настоящий ID тестового пользователя, допустимый уровень `pro` или `expert`, будущий `expires_at`. Обычный пользователь не должен изменять эту таблицу через браузер. Не выдавайте тестовый доступ случайному production-аккаунту.

Чтобы начать продажи, отдельно выберите провайдера, валюты и цены, настройте серверное создание checkout и подписанные webhooks с защитой от повторов, проверьте успешную оплату, отказ, возврат, отмену и истечение подписки. Переход на страницу «оплачено» или смена значения в localStorage никогда не должны выдавать доступ. Требуются также правила возвратов, поддержка и юридические условия для выбранных стран.

## 9. Перед публичным запуском

Проверьте восстановление резервной копии, HTTPS, лимиты базы и хостинга, журнал ошибок без секретов, политику хранения пользовательских данных и нагрузку. Исправьте оставшиеся замечания независимых проверок. Если публикация сломалась, используйте штатный откат Vercel на предыдущую проверенную сборку; не удаляйте таблицы и аккаунты. Откат приложения не отменяет миграцию базы автоматически.

Не обещайте автоматическое выполнение всех языков: часть заданий выполняется в локальных инструментах и проверяется самостоятельно. Не обещайте невозможность взлома: защита требует обновлений и проверки рабочего deployment. Локальные учебные черновики и сохранённая сессия доступны владельцу устройства/профиля браузера; они не являются зашифрованным хранилищем от человека, уже получившего такой доступ.
